## 1. 色彩令牌

所有颜色为**唯一取值**，禁止在设计或开发中出现同色系的近似色（如「再加一个浅一点的橘」）。

### 1.1 品牌色

| 令牌名 | 色值 | 用途 |
| --- | --- | --- |
| `orange-primary` | `#F5A623` | 主按钮底、选中态、进度填充、猫咪主毛色 |
| `orange-accent` | `#FF8A3D` | 悬停态、变化字符高亮、段号 |
| `orange-dark` | `#E08B33` | 按下态、选中文字、猫咪描边、强调文字 |

### 1.4 语义色

| 令牌名 | 色值 | 底色（浅） | 用途 |
| --- | --- | --- | --- |
| `ok` | `#4CAF7D` | `#EAF6F0` | 成功、可撤销、就绪状态点 |

> **规则**：语义色**只用于状态表达**，不参与品牌表达（不要用红色做装饰、不要用绿色做按钮）。任何状态下，颜色都不是唯一信息载体——必须同时有文字徽标。

### 1.5 对比度（WCAG AA）

| 组合 | 实测对比度 | 结论 |
| --- | --- | --- |
| `ink-1 #3A2A20` on `bg-cream #FFFBF5` | ≈ 12:1 | ✅ 远超 4.5:1 |
| `ink-2 #6B5B4D` on `bg-card #FFFFFF` | ≈ 7:1 | ✅ |
| `ink-3 #8A8178` on `#FFFFFF` | ≈ 4.6:1 | ✅ 临界通过，**不可再调浅** |
| **深棕 `#2A1A10`** on `orange-primary #F5A623` | **8.3:1** | ✅ **主按钮 / 危险按钮 / 复选勾一律用这个**（两主题同值） |
| 深棕 `#2A1A10` on `bad #E5544B` | **4.58:1** | ✅ 危险按钮文字 |
| ~~`#FFFFFF` on `orange-primary #F5A623`~~ | ~~2.03:1~~ | ❌ **已废弃，不再使用** |

> **v1.4 变更（P2-A / DEC-11）**：橘底上的前景色从「白字」改为**深棕 `#2A1A10`**。
> 原来那版只有 2.03:1，一直靠「14px 加粗算大字」的豁免勉强解释过去；改成深棕后是 **8.3:1**，
> 是真的达标了 —— 这一改**顺手把浅色自己的对比度问题也修掉了**，不只是为了深色好看。
> 统一管住三处：**主按钮文字 · 危险按钮文字 · 复选框的勾**（令牌 `--md-on-brand` / `--md-on-danger`）。

### 1.6 深色主题（P2-A / DEC-11）

**暖褐色深底**，不是冷灰黑。理由：本产品的全部卖点是「奶油白 + 橘猫」，冷灰会把暖萌感洗掉。

**三条规律**（记住这三条就不用背表）：

1. **品牌橘三色完全不变**（`orange-primary` / `accent` / `dark` 两主题同值）—— 猫毛色不该因为换主题就变。
2. **层级顺序保持「卡片最亮、凹陷槽最暗」**。浅色下 `bg-sunken #F7EFE3` 比卡片 `#FFFFFF` 暗；深色下它就必须比卡片 `#2E2119` 暗，即 `#1A1210`。**方向弄反了，页签的选中态就完全看不出来。**
3. **阴影从「暖棕」换成「纯黑」** —— 深底上暖棕影是看不见的（暖棕比深底还亮）。

**完整对照表**（单一真源是 `styles/tokens.css`，本节与它逐行对应）：

| --- | --- | --- |

**实现约定（已落地，不要改岔）**

| 项 | 做法 |
| --- | --- |
| 单一真源 | `src/renderer/src/styles/tokens.css`，**组件里禁止出现硬编码色值** |
| 挂载方式 | 深色块挂 **`@media (prefers-color-scheme: dark)`**，**不挂 `[data-theme]`** —— 这样首帧就不会闪（验收 TC-30）。`<html data-theme>` 仍会挂上，但**只用于冒烟断言** |
| 切换 | 主进程设 `nativeTheme.themeSource`，Chromium 的 `prefers-color-scheme` 自动跟随 → **零新增 IPC 通道** |
| 完整性 | 深色块必须覆盖 `:root` 里所有**非同值**令牌，由单测 `tests/p2a-theme.test.ts` 盯着，漏了会红 |
| 覆盖检查 | **`tokens.css` 之外 grep 色值必须归零**（验收 TC-32），不靠人眼 |

**已知取舍**（详见 §8）：深色下「关」状态开关轨道与卡片的对比约 1.6:1，低于 WCAG 对 UI 组件 3:1 的建议 —— 这是深色主题的行业普遍取舍（Material 深色同样不达标）；缓解是**开关状态由滑块位置表达、不依赖颜色**，所以不构成信息丢失。

## 2. 字体

### 2.1 字体家族

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 界面与正文（主） | **Noto Sans SC**（思源黑体） | 字重齐全、跨机一致，Windows / Mac 都装得上 |
| 品牌字 | **ZCOOL KuaiLe**（站酷快乐体） | **仅**用于产品名与猫咪状态文案，不用于正文 |
| 数字 / 技术信息 | **Inter** | 色值、文件名示例、序号、时间 |

> 字体文件若用于打包，请确认两份中文字体的授权（Noto Sans SC 为 SIL OFL，可商用；ZCOOL KuaiLe 为免费商用字体，但仍建议发布前复核一次）。

### 2.3 字重使用规则

- `400 Regular` — 所有正文、说明
- `500 Medium` — 需要轻微强调的标签、按钮
- `600 SemiBold` — 主按钮、卡片标题、选中页签
- `700 Bold` — 只用于各级标题
- 不使用 `300` 以下的细字重（中文小字会发虚）

## 3. 间距 · 圆角 · 阴影

### 3.1 间距（4px 基准）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `space-1` | 4px | 图标与文字间隙、微调 |
| `space-2` | 8px | 控件内部间隙（图标+标签） |
| `space-3` | 12px | 列表行内元素间距、卡片内小间距 |
| `space-4` | 16px | 卡片内边距、页面左右留白 |
| `space-5` | 20px | 分区间距 |
| `space-6` | 24px | 大区块间距、弹窗内边距 |
| `space-8` | 32px | 板块间距 |
| `space-12` | 48px | 画板外留白 |

> **不要出现 5 / 7 / 9 / 13 / 18px 这类「随手值」**。若 4px 台阶不够用，用 4 和 8 的中间值 `6px`（可接受），其余一律回到台阶上。

### 3.2 圆角

| 元素 | 圆角 |
| --- | --- |
| 卡片、弹窗、画板 | 16px（画板外框 18px） |
| 按钮 | 12px |
| 输入框、数字框、下拉 | 10px |
| 色块、缩略图、图标按钮 | 8px |
| 徽标 | 6px |
| 页签 / 段控容器 | 14px（内部页签 10px） |
| 全圆梗（状态点、胶囊） | 取高度一半 |

> 逻辑是「**面积越大越圆**」：卡片最圆、输入框次之、徽标最小。反过来会显得生硬。

### 3.3 阴影（只用两层）

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `shadow-card` | `0 4px 16px rgba(180,120,60,.12)` | 卡片默认 |

- 组内顺序：启用序号 → **位置** → **类型** → 参数 → 示例行。位置放在类型之前，沿用 P0 的排布（改动最小），也正是列需求时的语序。
- 「步长」→ **增量**、「补零位数」→ **位数**、「序号位置」→ **位置**：与小白用户自己的说法对齐。
- 组标题仍然是「**启用序号**」，**不跟着类型改名** —— 它是这个组的开关。

**规则摘要的新写法（P3 第 1 批 / DEC-15）**

第 1 批把序号段的措辞与界面用词对齐（「步长」→**增量**、「补零」→**位数**），并把**类型与位置**写出来：

| 类型 | 摘要长什么样 |
| --- | --- |
| 数字 | `序号(数字 / 起始 4 / 增量 4 / 位数 0 / 排在最前)` |
| 字母 | `序号(字母 / 起始 1 / 增量 1 / 排在最前)` |
| 随机字符 | `序号(随机 6 位 / 排在最前)` |
| 时间 | `序号(时间 2026-09-18 起每天 / 排在最前)` |

> **⚠️ 新老记录两种写法是刻意允许的**：`buildRuleSummary` 的返回值会写进 `history.json` —— **上了这一批之后的新记录**是新写法，**老记录**保持旧写法（`序号(起始 1 / 步长 1 / 补零 3 / 排在最后)`）。摘要是纯显示字符串、不参与任何解析，两种写法各自自洽。
> **因此绝对不要为了「新老一致」去写一个迁移改老记录** —— 那等于去改已经落盘的历史数据，而历史数据是**撤销功能的依据**。这与上面那条「只在渲染层截断」是同一条纪律。

> 新文案先讲**什么场景下用得上**（别的程序 / 定时任务帮你改名），再说明**看不懂也有教程**。**先给理由，再给术语。**

示例命令（**只给一条**，保持简洁）：

```
maodie.exe --rename --dir "D:\下载\素材" --delete "广告" --yes
```

> **CLI 的安全底线（与界面完全一致）**：默认**不覆盖**任何已有文件、冲突**跳过**；`--auto-seq` 才自动加序号。

> 理由：命令行里**没有预览界面**，而这个产品的调性是「绝不毁数据」—— 默认只读，让用户先看一眼再决定。
> （完整 CLI 语法见 `接口文档.md` §10，**已定稿**；`P2-C轻量设计确认.md` §3.3 是当时的草案，以接口文档为准。）

### 5.6 SCR-08 命令行图文教程（P2-C 增量 / DEC-13）

> **要解决的问题**：命令行入口（EL-114 ~ EL-116）做完后，**小白用户打开看到「maodie.exe --rename --dir …」只会一脸茫然**。
> 光有「复制命令」按钮不够 —— 用户不知道这条命令是干嘛的、要粘到哪里、粘完会发生什么。所以补一个**三步图文教程**。

| 顶部说明 | 一段引导（12.5 `ink-2`）：「如果你想一次改很多文件夹里的文件，或者把它写进自己的批处理脚本里，可以用命令行模式。三步就能上手：」 |
| 步骤页签 | 三个 `第 N 步` 小页签（复用既有 `md-tab` 样式），可**直接点跳**任意一步，不强制顺序看 |

**步骤内容（三步）**

| 步 | 标题 | 图（SVG 线框示意） | 文字要点 |
| --- | --- | --- | --- |
| 1 | 第一步 · 打开命令行 | 键盘上的 **Win + R** 两个键高亮 + 弹出的「运行」输入框（里面写着 `cmd`）+ 一个光标闪烁 | 按 Win + R 打开「运行」，输入 cmd 后回车，会弹出一个黑色窗口。**这就是命令行 —— 它和软件界面做的是同一件事，只是用打字代替点鼠标** |

| 3 | 第三步 · 先试一遍，再真改 | 黑窗口里两行输出：一行是**预演**结果（`预演：广告素材-01.png → 素材-01.png`），另一行在末尾补了 `--yes` | 先**不加 `--yes` 跑一遍**，它只会把打算改成的名字列出来，**一个文件都不动**。确认清单没问题后，在末尾补上 `--yes` 再跑一次，才真正改名 |

| 尺寸 | `viewBox="0 0 240 150"`，按容器宽度自适应缩放 |
| 黑窗口底色 | `#0c0c0c`（Windows 命令提示符的默认黑）、窗口标题栏 `#2b2b2b`、屏内文字 `#cccccc` |
| **不随主题翻转** | 这三色定义在 `src/shared/theme.ts` 的 **`CLI_DEMO_COLORS`**，**刻意不进 `tokens.css`**。<br>**理由**：它画的是「**现实里那台机器上的黑窗口**」，不是本软件的界面。把黑窗口在深色模式下改成浅灰，用户会以为「深色模式连 cmd 都变色了」—— 那与他要看到的真实情况**不一致**。 |
| 无障碍 | 每张图带 `role="img"` + `aria-label`（描述图意，如「按 Win+R 打开运行框，输入 cmd」），**不是纯装饰** |
| 安全性 | 纯静态 SVG 字符串（无 `<script>`、无 `<image>` 外链），经 `v-html` 渲染；已在 `eslint.config.js` 对 `CliGuideModal.vue` 放行 `vue/no-v-html` |

> **为什么用线框示意图而不是截图**：截图会随系统版本、终端字体、窗口大小变化而**失真**，用户照着截图反而对不上自己的屏幕。线框只保留「按键」「四段结构」「预演输出」这些**位置关系**，跨版本稳定。
> **为什么不放视频/GIF**：体积与维护成本都不划算，而这三步的信息量用一张静态图 + 一句话能讲清。

> **用户已明确不做的**：一键生成 `.bat` 文件。教程**只教怎么用，不代用户往硬盘上写任何脚本** —— 那会变成一个新的「未经确认就落盘」的风险面。

### 6.3 状态优先级与会话约束


- 执行中（ST-03）**不接受** ST-02 抢占：拖拽入列仍可进行，但**不切换形象**，只更新列表。

1. **动作不得有歧义**：严禁「双肢快速上下抽动 + 躯干抖动 + 张嘴」这类组合；新增动作必须先做一遍「会不会被想歪」自查。

## 7. 动效规范

| 场景 | 时长 | 缓动 | 位移 / 变换 |
| --- | --- | --- | --- |
| 按钮按压 | 120ms | ease | `scale(0.96)` |
| 按钮悬停 | 180ms | ease | 上浮 1px + 阴影加深 |
| 弹窗出现 | 220ms | `cubic-bezier(.34,1.4,.64,1)` | `scale(0.92 → 1)` + 淡入 |
| 猫咪状态切换 | 320ms | `cubic-bezier(.34,1.5,.64,1)` | Q 弹感，只换表情 / 姿态 |
| 预览刷新 | — | — | 200ms 防抖后**立即重绘，无过渡动画**（避免列表闪动） |
| 进度推进 | 180ms | linear | 宽度推进 |

## 8. 无障碍（WCAG AA 基线）

| 项 | 要求 |
| --- | --- |
| 对比度 | 正文 ≥ 4.5:1；大字（≥14px 加粗）≥ 3:1。**浅 / 深两套主题分别实测**，实测值见 §1.5 / §1.6 |
| 焦点可见 | 所有可聚焦元素 2px `orange-primary` 描边，描边不遮挡内容；Tab 顺序「操作区 → 列表 → 规则区 → 动作区」 |
| 不依赖颜色 | 冲突 / 非法状态除标红外，**必须有文字徽标**（重名 / 非法） |
| 键盘操作 | `Enter` 触发主操作；`Esc` 关闭弹窗；`Ctrl+O` 添加文件；`Ctrl+Z` 进入撤销页；`Delete` 移除列表行 |
| 动效可关 | **设置弹窗（SCR-07）** 提供「减少动画」开关。⚠️ 此前这个开关**写好了却没有入口**（用户只能手改 `prefs.json`），P2-A 建设置面时补上 |
| 触控 / 点击目标 | 所有可点元素 ≥ 26px；主流程按钮 ≥ 42px |
| 文字缩放 | 界面在 200% 文字缩放下不溢出、不重叠 |

### 8.1 深色主题的已知取舍（如实记录，不当成达标）

| # | 项 | 实测 | 说明 |
| --- | --- | --- | --- |
| 1 | 深色下「关」状态开关轨道 vs 卡片 | 约 **1.6:1** | 低于 WCAG 对 UI 组件 **3:1** 的建议。这是深色主题的**行业普遍取舍**（Material 深色同样不达标）。**缓解**：开关的**状态由滑块位置表达、不依赖颜色**，所以不构成信息丢失。为此专门加了令牌 `--md-switch-track-line`（深色 `#5E4A3B`）补描边，让轨道至少能看见 |
| 2 | 深色下滑块 vs 橘轨道 | 约 **2.0:1** | 同样低于 3:1。与浅色现状**一致**，未引入新问题 |
| 3 | 极浅文字 `ink-4` | 深色 2.5:1（浅色 2.2:1） | 定位就是占位 / 极次要提示，**不得承载必要信息**（如错误原因、必读说明） |

### 8.2 令牌覆盖率（可自动检查，不靠人眼）

**`tokens.css` 之外 grep 色值必须归零。** 这条要落成一条可执行的检查（脚本或单测）：扫 `styles/` 与 `components/`，命中 `#RRGGBB` / `rgba(` 即失败，`tokens.css` 白名单。

> 背景：P2-A 动深色之前，`base.css` 与 `animations.css` 里有 **23 处硬编码色值**（白勾、白滑块、浅色遮罩、亮白的咬名字卡片…），这些不跟主题走，直接做深色会漏出一片白。完整清单与替换映射见 `P2-A轻量设计确认.md` §5.2。

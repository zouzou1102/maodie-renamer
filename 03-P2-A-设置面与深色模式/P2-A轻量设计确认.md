3. 它顺手把 **P0 的一个遗留缺口**补上（见 §1）。

## 1. 两个必须先说的发现

### 1.1 这个软件目前没有任何「设置」入口

`Prefs` 里有 4 个设置项，但**界面上一个都改不了**：

| 设置项 | 代码里 | 界面上 |
| --- | --- | --- |
| 音效 `soundEnabled` | ✅ 已在用（`task.ts` 播放音效时读它） | ❌ 无入口 |
| 减少动画 `reduceMotion` | ✅ 已生效（挂到 `data-reduce-motion`） | ❌ 无入口 |
| 二次确认阈值 `confirmThreshold` | ✅ 已在用 | ❌ 无入口 |
| 主题 `theme` | ⚠️ 只有 `'light'` 一个值 | ❌ 无入口 |

全仓库检索确认：`setPrefs` 只在 `stores/prefs.ts` 内部被调用，**没有任何组件引用过它**。

> **这意味着一件事**：交互说明 §9 与设计规范 §8 里那条无障碍要求「**设置中提供『减少动画』开关**」，**目前是达不到的** —— 开关写好了、也能生效，但用户根本打不开。这是个 P0 遗留缺口，本批一并补上。

### 1.2 深色模式不能只加一个覆盖块

`tokens.css` 之外还有 **20 处硬编码色值**（`base.css` 13 处、`animations.css` 7 处）。<br>（**v1.3 修正**：v1.0 ~ v1.2 写的是「23 处 / `base.css` 16 处」，与 §5.2 表格本身的行数（13 + 7）对不上 —— 是清点口径笔误，已按 `git diff` 逐行复算改正）这些不跟主题变，直接做深色会漏出一片白/浅色。**深色模式的真实工作量是「先把这些抽成令牌」，而不是「写一个 `[data-theme=dark]` 块」。**

完整清单与替换映射见 §5。

## 2. 设置入口

| 项 | 规格 |
| --- | --- |
| 位置 | 标题栏右侧、窗口三键（最小化 / 最大化 / 关闭）的**左侧** |
| 按钮 | 38×30px、圆角 7px，与三键同尺寸 |
| 图标 | **滑杆**（不是齿轮），14px |
| 默认态 | 底透明、图标 `ink-2` |
| 悬停态 | 底 `brand-tint`（新令牌）、图标转 `orange-dark` |
| 深色态 | 图标 `ink-2` 深色值 `#CBB9A8`（比浅色更亮才看得清） |

> **为什么刻意不用齿轮**：P1 刚给规则区的「⚙ 进阶设置」折叠条用了齿轮（EL-056）。同一个屏幕上出现两个齿轮，用户会以为它们是同一个东西。滑杆是同样通用的「设置」隐喻，且视觉上能区分。

## 3. 设置弹窗（新 SCR-07）

复用现有模态样式，**零新视觉**：480 宽 / 圆角 16px / 内边距 24px / 行间距 16px / 遮罩 `scrim` / 220ms `cubic-bezier(.34,1.4,.64,1)`。

### 3.1 只放三项

| 分组 | 项 | 控件 | 默认 | 说明文案 |
| --- | --- | --- | --- | --- |
| 外观 | **主题** | 三选一：跟随系统 / 始终浅色 / 始终深色 | **始终浅色** | 「跟随系统」会跟着 Windows 的深浅色自动切换。 |
| 声音 | **音效** | 开关 | 开 | — |
| 无障碍 | **减少动画** | 开关 | 关 | 开启后猫咪状态切换只换表情、不做位移，动效时长归零。 |

**为什么不放「二次确认阈值」**：PRD 从头到尾没要求过这个旋钮，它是内部常量。按 YAGNI 不暴露 —— 顺带也避免给小白多一个看不懂的开关。如果将来真有用户抱怨「10 个就弹太烦」，再单开一条。

### 3.2 交互

- **即改即生效**，没有「取消」按钮 —— 所以底部只有一个「完成」。**点「完成」即关闭弹窗**（不刷新、不跳转、不二次确认）。
- 关闭方式三者等价：点遮罩 / 按 `Esc` / 点「完成」。
- 主题切换是**即时**的：切换后整个界面（含已打开的弹窗）立刻换色。

## 4. 深色配色：暖褐色深底

**这是本批最核心的一个决定，也是唯一一个「审美取向」决定。**
市面上的深色模式几乎都是冷灰黑，但本产品的全部卖点是「奶油白 + 橘猫」，冷灰会把暖萌感洗掉一半。所以用**暖褐色（espresso）**。

1. **品牌橘三色完全不动**。猫毛色不该因为换主题就变。

3. **层级顺序保持「卡片最亮、凹陷槽最暗」**。浅色下 `bg-sunken #F7EFE3` 比卡片 `#FFFFFF` 暗；深色下它就必须比卡片 `#2E2119` 暗，即 `#1A1210`。**方向弄反了，页签的选中态就完全看不出来。**

> ⚠️ **一处修正**：我在方案讨论时给的「凹陷块 `#33261F`」是**错的** —— 那比卡片还亮，方向反了。表里的 `#1A1210` 是修正后的值，画板用的也是这个。

- `--md-orange-dark` 在深色下不是「深橘」，而是「强调橘」（值也确实是同一个）

**本批选择：保留名字，在 `tokens.css` 里把每个令牌「在两种主题下各扮演什么角色」写清楚**（加一段注释，不靠人记）。将来若要做语义重命名，那是一个独立的小批次，不影响本批交付。

## 6. 橘底上的前景：两主题统一用深棕

> **v1.1 修订**：v1.0 原本只在深色下翻转前景色；负责人拍板「**两个主题统一**」，故改为两套主题共用同一个值。

**浅色现状**：主按钮是**白字配橘底**，对比只有 **2.03:1** —— 连「大字 3:1」都不到，当时是靠「14px 加粗算大字」的说法勉强解释过去。

**改为两主题统一后**：

| 组合 | 对比度 | 结论 |
| --- | --- | --- |
| 白字 on `#F5A623`（原浅色） | 2.03:1 | ❌ 不达标 |
| 深棕 `#2A1A10` on `#F5A623`（**新，两主题**） | **8.3:1** | ✅ 远超 4.5:1 |

**这不是单纯的观感统一，而是一次净改善** —— 顺手把浅色自己一直存在的对比度问题也修掉了。

统一后由两个令牌管住三处：

1. 主按钮文字 → `--md-on-brand`
2. 危险按钮文字 → `--md-on-danger`（深棕 on `#E5544B` = **4.58:1**，浅色原来白字是 3.66:1）
3. **复选框的勾**（现在硬编码 `fill: #ffffff`）→ `--md-on-brand`（深棕勾 on 橘底 = 8.3:1，原来白勾是 2.03:1）

另外把开关滑块也一并对齐：`--md-switch-thumb` 两主题都用 `#FFFFFF`（v1.0 里深色用的是 `#F2E9E0`）。少一个主题差异，少一处要维护的值。

> **对观感的影响**：浅色下主按钮从「白字」变「深棕字」。这是本批唯一一处**改变浅色现有观感**的地方 —— 因为是你要求统一的，且它同时修掉了对比度问题，所以我认为值得。如果你事后觉得浅色还是白字好看，那就得退回「两主题不一致」，两者只能选一个。

## 7. 主题切换机制（零新增 IPC 通道）

`接口文档` 把事件通道固定成 3 个，所以**不能加「主题变了」的广播**。好在不需要：

```
1. 主进程设  nativeTheme.themeSource = 'system' | 'light' | 'dark'
2. 渲染层只监听  matchMedia('(prefers-color-scheme: dark)')
   —— Chromium 的 prefers-color-scheme 会自动跟随 themeSource，
      所以系统切换与用户手动选择都能收到，无需新通道
3. <html> 的 data-theme 跟着这个 media query 走，CSS 变量整块切换
```

### 7.1 首帧不能闪（这条不做就等于没做）

`Prefs` 是异步从主进程读的。如果先渲染浅色、再切深色，用户开软件会**先看到一下白底再变深**。

**做法（v1.3 修正 —— 原写「渲染层首帧前把 `data-theme` 挂上」，那仍然会闪）**：

1. **深色值挂 `@media (prefers-color-scheme: dark)`，不挂 `[data-theme='dark']`。** 挂属性就得等 JS 跑起来才有那个属性，而 JS 跑到时第一帧早就画出来了 —— 属性方案**物理上做不到不闪**。
2. 主进程在 `new BrowserWindow` **之前**执行 `nativeTheme.themeSource = theme`（Chromium 因此**在首帧就知道**该用深色），并用 `windowBackgroundFor(isDarkNow(theme))` 定窗口底色。
3. `<html data-theme>` 仍然挂上，但**只用于冒烟断言与排查，不参与样式选择**。

> 一句话：**首帧的颜色由 CSS 媒体查询 + 主进程建窗前的两次设置共同保证，与 JS 何时执行无关。**

### 7.2 顺带要处理的

| 项 | 做法 |
| --- | --- |
| Windows 原生 UI（滚动条、右键菜单） | `nativeTheme.themeSource` 会一并影响，不需要额外处理 |
| 「减少动画」与主题共存 | 都挂在 `<html>` 的 `data-*` 上，互不干扰（`data-reduce-motion` 机制已跑通，照抄即可） |
| 猫咪形象 | **不需要改**。橘色 SVG 在暖深底上更好看 |

「肯定不够但想不到更多」很正常。下面是我按这个产品的实际形态梳理的候选，**等有用户反馈时再挑 1~2 个**，现在一行都不做：

| 候选 | 为什么可能有用 | 成本 |
| --- | --- | --- |
| 改完后**自动清空列表** | 连续处理多批文件的人不想每次手动「清空」 | 低 |
| **默认序号补零位数 / 起始值** | 常做发票归档的人每次都填一样的值 | 低 |

| **「咬名字」动画单独开关**（现在只有全量「减少动画」） | 有人喜欢猫、有人嫌吵 | 低 |
| **记住上次窗口位置 / 启动自动聚焦列表** | 高频用户的效率诉求 | 低 |
| **界面缩放**（现在藏在不可见的应用菜单里） | 小屏 / 高 DPI 用户 | 中 |
| **一键把当前规则存成模板** | 与 P2-B 的模板库天然衔接 | 中 |

> **我的建议：别提前堆。** 设置项一多，「设置」这个入口对小白就从「可探索」变成「不敢点」。等真实反馈再挑。

### 16.3 交叉核验：深色那一帧「真的画出来了」

computed style 说对了，不等于屏幕上的像素真的变了。所以另外从**真实截图**里取像素复核：

| 取样位置 | 切换前 | 切换后 |
| --- | --- | --- |
| 卡片区（弹窗内）| `(255, 255, 255)` | `(46, 33, 25)` |
| 弹窗外的左侧区 | `(255, 255, 255)` | `(46, 33, 25)` |
| 关掉弹窗后的列表卡片 | `(255, 255, 255)` | `(46, 33, 25)` |

`(46, 33, 25)` 正是深色 `--md-bg-card` = `#2E2119`。**弹窗内外三处取样一致 → 是整窗换底，不是只有弹窗好看。**

### 16.4 落地时发现并修掉的三处「文档写了、代码没跟上」

| # | 缺口 | 为什么危险 |
| --- | --- | --- |
| 1 | `icon-设置.svg` 只加到了 `切图资源/icons/`，**没加运行时目录** `src/renderer/src/assets/icons/` | 切图目录是「给人拿的」，运行时读的是 assets —— 只加前者，按钮上是个**空图标** |
| 2 | `app.ipc.ts` 的 `sanitizePatch` **没有 `theme` 字段** | 渲染层改主题会被**静默丢弃**，界面看起来一切正常 |
| 3 | `prefs-store.ts` 把 `theme` **硬钉成 `'light'`** | 无论存了什么，读出来永远是浅色 |

第 2、3 处是同一类故障：**「值永远不变，但界面没有任何异常」** —— 光靠点界面发现不了。现在由单测 + 冒烟断言盯死，做法也写进了 `技术方案文档.md` §4.4。

关于本稿：这是一份规格稿（HTML 规格页），不是画布画板 —— 本轮画布服务连不上，先用能直接打开、能逐像素核对的方式出稿。 所有颜色 / 圆角 / 间距均取自 tokens.css 既有令牌，零新增色值；深色块与产品实现一样挂在 prefers-color-scheme 上。 画布恢复后我会把同样的内容原样搬成画板。
全稿统一把示例文件名取作「【素材】」 —— 与你举的例子同一个名字，这样一眼就能核对结果对不对。

一 · 这张稿要解决什么

现在的序号只有「数字 + 补零」一种，位置只有「最前 / 最后」两档。这一批把它扩成 4 种类型 × 3 档位置，并加一行「当场算给你看」的示例。

二 · 四种编号类型

「类型」就是这个新下拉的全部内容。切类型只换参数行，位置、示例、其他开关都不动。下面四张是同一个序号组的四个状态（其余部分同图 1，不再重复）。位置统一取「排在最前」，好跟你的例子对齐。

三 · 位置：两档变三档

新增第三档「插在第 n 个字符后」。选中它时，右边就地长出一个数字框 —— 不另开一行，因为位置本身还是一个控件。

四 · 深色模式

新控件全部复用既有类，没有新增一个色值，所以深色自动成立。下面两张是深色下的实际取值。

五 · 规格与状态

项规格
字号 / 字重标签与既有「起始 / 步长」一致：12.5px / 500；输入框 13px / 400；数字与日期框用 font-num（Inter 等宽数字，位数对齐才看得清）
控件高度全部沿用 --md-ctrl-h = 40px。可点击目标 ≥ 24×24 CSS px（WCAG 2.5.8 AA）达标
「换一批」按钮高 28px、内边距 0 10px、圆角 radius-badge 6px、底 bg-card、描边 line-strong、字 12px ink-2；悬停时字与描边转 orange-dark。既有按钮类只有 22px 高，够不上 AA，所以这个新按钮单独给 28px
输入框宽度起始 / 增量 / 位数 / 长度 / 增量（天）：104px（沿用既有 md-input--num）；「第 n 个字符后」64px 居中；起点日期框 142px
间距组内行间 space-2 = 8px；参数行内项间距 space-3 = 12px；组内边距 space-2 = 8px。全部沿用既有台阶，不新造 5 / 7 / 9 这类随手值
示例凹槽底 bg-sunken、圆角 radius-input 10px、内边距 8×12px、槽内 code 提亮回 bg-card（与 P1 的「当场演示」同一套做法，不新造样式）
颜色新名 / 激活 orange-dark　新名底 highlight-bg　凹槽 bg-sunken　说明字 ink-3　警示 bad。全部为既有令牌
对比度标签 ink-2 on 组底 bg-warm：浅色 7.0:1、深色 7.5:1，都远超 AA 正文线（4.5:1）。说明字 ink-3：浅色 4.9:1、深色 5.1:1，也过线。示例里的新名 orange-dark on highlight-bg：浅色 3.6:1、深色 3.5:1 —— 它是强调而不是正文（正文是左边那个原名字），且已加粗到 500，属装饰性强调；如果你希望它也更硬，我可以把它换成 ink-1 + 橘色底纹，那就到 8:1 以上
禁用态「启用序号」未勾选时，位置 / 类型 / 参数 / 换一批整组置灰不可点（沿用 md-input:disabled / md-select:disabled），示例行整块不显示 —— 没启用就没什么可示例的，显示一行空槽只会让人以为坏了
键盘Tab 顺序：位置 → 类型 → 起始 → 增量 → 位数（或长度 → 换一批）；选中「插在第 n 个字符后」时焦点自动落到那个数字框。焦点环沿用 2px orange-primary + focus-ring
动效只有参数行增减带来的高度变化，时长沿用 dur-hover 180ms。开启「减少动画」后归零（既有全局规则覆盖，无需新增）
主题本批不新增任何令牌，因此也不需要在 tokens.css 的深色块里补任何值 —— 这是「零新增令牌」最实际的好处

六 · 必须一起改到的地方（漏一处就出静默 bug）

这一节不是给你看的，是留给实现的：详细理由见文档 §7。

位置不改会发生什么
src/main/ipc/rename.ipc.ts 的 sanitizeRule最阴的一处。那里是逐字段白名单，新字段会被静默丢掉 —— 预览是对的、执行是错的，而界面上一点异常都没有。这个项目已经被同一类问题坑过一次
src/shared/preview.ts 构造 RuleContext 那一行随机字符拿不到种子 → 每个文件算出同一个随机串，或者预览与执行不一致
src/shared/rule-engine.ts 里的 seqBefore 布尔判断第三档位置会静默退化成「排在最后」，而界面照常显示「插在第 n 个字符后」
src/shared/cli-args.ts 的 --rule 解析命令行改这几个新参数会被忽略，界面与命令行行为不一致
src/renderer/src/stores/rule.ts 的 clamp()新的数值项失去越界保护，可以填出负数、超长
src/shared/rule-summary.ts历史记录摘要说不清当时用了哪种编号、插在哪

※ 日期加法不能用 new Date()：时区与夏令时会把日期挪一天。要用纯整数的公历日序算法（年月日 → 天数 → 加 n 天 → 还原回去），这样跨月、跨年、闰年都确定，也才写得出单测。

## 1. 先讲清五件事

### 1.1 不是第五种模式，是规则化模式里的**三个新变量**

和 P3-1 把「编号类型」做成序号组里的一个下拉是同一个判断：**「新名从哪儿来」不是另一条路，是规则化模式里的一个新变量**（总规划 §3 的 B 方案，已拍板）。

所以本批 `RuleConfig.mode` **一个字都不动**，仍然只有 `delete / replace / rule` 三种。

### 1.2 三个变量，写在前缀 / 后缀里（和 `{n}` `{d}` 同一个位置）

现在前缀 / 后缀支持 `{n}`（序号）和 `{d}`（日期）。本批加三个：

| 变量 | 取什么 | 例子（原名 `IMG_0001.JPG`） |
| --- | --- | --- |
| `{创建}` | 文件的**创建**日期 | `2026-09-18_IMG_0001.JPG` |
| `{修改}` | 文件的**最后修改**日期 | `2026-09-20_IMG_0001.JPG` |
| `{大小}` | 文件的**大小** | `2.4MB_IMG_0001.JPG` |

> **为什么放前后缀、不做成「自动追加」**：`{n}` 与 `{d}` 除了能在前后缀里写，还有一个**自动位置**（序号的位置三档、日期的自动片段），所以它们需要「启用开关」。**属性没有「自动位置」这个概念** —— 它只有「用户写了才出现」。所以本批**不加「启用属性」开关**，加了反而会让人以为「勾上就会自动加进名字」。

### 1.3 属性在**加入列表那一刻**读一次，之后不再刷新

`fs-scan` 在把文件加进列表时本来就调了 `fs.lstat`（§2.1），本批就是**顺手把结果里的三个值存下来**。之后：

- 预览与执行**都用这一份**，执行时**不重新读盘**。
- 这样「**预览 ≡ 执行**」才成立 —— 否则「预览时文件是 10:00 改的、执行前又被改成 11:00」会让两边算出不同的名字。**与 P3-1「时间起点冻结进规则」是同一条纪律。**

> 界面要在属性组下面写一句常显提示：**「属性是你把文件拖进来那一刻读的，之后不再刷新」**。不写这句，用户会遇到「我明明刚改过这个文件，名字里还是旧日期」并当成 bug。

### 1.4 属性取不到时**展开成空串**，不报错、不置灰

| 情形 | `{大小}` 展开成 | 为什么 |
| --- | --- | --- |
| 文件夹 | **空串** | Windows 里文件夹的 `lstat().size` 要么是 0、要么是目录项本身的大小，**都不代表里面内容的总和**；要算总和得递归遍历内部，而本项目为安全**不为算文件夹大小去递归**（`DEC-01` 的本意是「**不跨 symlink / junction 递归**」，防死循环 / 防复制系统目录；P3-7 文件夹合并才是第一次主动递归，且同样严格不跨这两者）。所以文件夹**没有**「大小」这个概念 |
| 0 字节的真文件 | **`0B`** | **这是一个真实的、合法的值**，不能和「不可用」混为一谈（见下） |
| 三种属性变量 | 同上 | 一律空串，不弹错、不把该项标红 |

> ★ **`0` 与「不可用」必须分开**：`{大小}` 为空串是「这个对象没有大小」，`0B` 是「这个文件确实是空的」。若把文件夹也算成 `0B`，用户会以为自己的文件夹是空的。所以实现上用 **`null` 表示不可用、`0` 表示真的空**，绝不用 0 兼任两种含义。

### 1.5 本批**不碰**扩展名、不碰文件名以外的任何东西

`EX-07` 扩展名保护照旧：属性变量只进「新名主体」，`.JPG` 一个字符都不动。

## 2. 界面形态

### 2.1 先说一个能让实现变简单的实测事实

`src/main/services/fs-scan.ts:77` **已经在 `await fs.lstat(fullPath)`** 了 —— 而 `fs.Stats` 里 `size` / `mtime` / `birthtime` **全都有**。

**所以本批「零额外磁盘 IO」**：不是多扫一遍盘，而是「把已经读到的三个值存下来」。成本 = 加 3 个字段 + 3 行赋值 + 过一遍 IPC。

### 2.2 规则区加一个「属性组」

放在**日期组下面**（两个都是「变量来源」的组，挨着放），「保留原文件名」上面：

```
┌─ 序号组（bg-warm）────────────────────────────┐
│  … 启用序号 / 位置 / 类型 / 参数 / 示例 …      │
└───────────────────────────────────────────────┘
┌─ 日期组（bg-warm）────────────────────────────┐
│  … 启用日期 / 日期格式 / 提示 …                │
└───────────────────────────────────────────────┘
┌─ 属性组（bg-warm）★ 新增 ─────────────────────┐
│  属性  创建日期 {创建}   修改日期 {修改}     │   ← 只读展示（不是输入框）
│        文件大小 {大小}                        │
│  注    创建 / 修改日期用的是上面「日期格式」那一档 │   ← #5：改那里，三处一起变
│  大小  [ 自动            ▾ ]                  │   ← ★ 新增控件（EL-131）
│  示例  2026-09-18 · 2026-09-02 · 2.4MB        │   ← 拿固定假属性试的，见 §3.3
│  属性是你把文件拖进来那一刻读的，之后不再刷新。 │   ← 常显提示
└───────────────────────────────────────────────┘
```

**为什么「属性」那一行是只读展示而不是可编辑**：这三个不是「设置项」，而是**变量名**。用户在这里要做的事是「知道有这么三个变量、并知道它们长什么样」，不是「填一个值」。所以做成**展示 + 可点一下就插入到前缀/后缀**（点一下把 `{大小}` 追加到前缀末尾 —— 便宜且好用）。

**为什么要多一行「注」**：`{创建}` / `{修改}` 的日期格式**复用日期组那个「日期格式」下拉**，不新增第二个控件（`#5`，已确认）。但那个下拉待在**日期组**里 —— 用户若不启用日期、只想用 `{创建}`，会**不知道去哪找它**。所以属性组里放一行常显说明，**让这个「两处共用一份设置」的关系在原地就能被看见**。这一行和 §2.3 的提示行是同一类东西：**不加，功能也在，只是没人找得到。**

**为什么「大小」只有一个下拉、没有第二个控件**：
- 单位：`自动` / `字节 B` / `KB` / `MB` / `GB`（默认 `自动`）。
- **小数位固定 1 位，B 这一档例外（整数）** —— 这是我自己定的，理由见 §5.②，**不新增第二个控件**。

### 2.3 ★ 前缀 / 后缀下面那行提示**必须改**（否则功能等于不存在）

现在那行写的是：

> 支持变量 `{n}` 序号、`{d}` 日期 —— 变量需先勾选下方对应开关

本批要改成：

> 支持变量 `{n}` 序号、`{d}` 日期（**需先勾选下方对应开关**）、`{创建}` 创建日期、`{修改}` 修改日期、`{大小}` 文件大小（**写上就生效，不用开关**）

**为什么这一行不改是本批最容易被忽略的「静默」问题**：不改的话，功能**完全正常**、测试**全绿**、界面上**一点异常都没有** —— 只是**没有任何用户会知道有这三个变量**。这不是代码 bug，是「功能等于不存在」，而且没有任何断言能抓到它（除非专门为这行文案写一条）。所以它要进 §7.5 那张表。

### 2.4 其它既有控件都不动

位置 / 类型 / 参数 / 示例行 / 日期组 / 保留原文件名 / 进阶设置 / 底部开关 —— **一个字都不改**。

## 3. 完整定义

### 3.1 变量一览

| 变量 | 类型 | 取值范围 | 不可用时 |
| --- | --- | --- | --- |
| `{创建}` | 日期串 | `YYYY-MM-DD`（**本机本地时区**，见下） | 空串 |
| `{修改}` | 日期串 | 同上 | 空串 |
| `{大小}` | 大小串 | 按 §3.4 的规则渲染 | 空串（**文件夹**） |

三个变量都**只在前缀 / 后缀里生效**（和 `{n}` `{d}` 一样，不进「原文件名」主体）。

### 3.2 ★ 创建日期必须用 `birthtime`，**不能用 `ctime`**

Node 的 `fs.Stats` 在 Windows 上：

| 字段 | 含义 | 适合当「创建时间」吗 |
| --- | --- | --- |
| `birthtime` | **真正的创建时间** | ✅ **用它** |
| `ctime` | **元数据变更时间**（改名、改权限、改属性都会刷新） | ❌ **绝不能用** |
| `mtime` | 内容最后修改时间 | 用于 `{修改}` |

**为什么这条要单独写一段**：`ctime` 在别的语言/平台常被当作「创建时间」，而**这个产品干的就是改名** —— 一旦用错，用户在预览里看到的时间是「**上一次改名那一刻**」，而且**这一批改名之后，下次再跑，时间又全变了**。界面上没有任何异常。这属于本项目一直在防的那一类「值不对但看起来正常」。

### 3.3 ★ 日期用**本地时区**算，不能用 `toISOString()`

`2026-09-18 02:00`（本地，UTC+8）的文件，`new Date(ms).toISOString().slice(0,10)` 得到的是 **`2026-09-17`** —— 整整差一天，而且**只在凌晨 0:00–8:00 之间创建的文件上出现**。批量改名的日期一旦差一天，是整批文件都错，用户很难当场发现。

**做法**：用本机本地日期分量（`getFullYear` / `getMonth` / `getDate`）拼 `YYYY-MM-DD`。项目里已经有这个写法（渲染层 `todayString()`），本批把它**下沉到 `shared/`** 成一个共用纯函数，让「今天」和「这个文件的属性日期」走同一套逻辑（放 `shared/` 才跑得进单测）。

### 3.4 大小的渲染规则

| 单位 | 规则 | 例（真实值 2 516 582 字节） |
| --- | --- | --- |
| **自动**（默认） | 选**第一个让数值 ≥ 1** 的单位 | `2.4MB` |
| 字节 B | 整数，无小数 | `2516582B` |
| KB / MB / GB | 保留 **1 位小数** | `2458.0KB` / `2.4MB` / `0.0GB` |
| 换算基数 | **1024**（1 KB = 1024 B），不是 1000 | — |

> 单位用 `B / KB / MB / GB` 这四个，**不加 `TB`** —— 10000 个文件上限、且是桌面改名工具，TB 级单文件不属于要照顾的场景。

### 3.5 ★ 示例行怎么显示属性变量（与 P3-1 的决定有关）

P3-1 定过：示例行**固定拿「【素材】」试，不跟随列表里的真实文件**（理由：跟真实文件走的话，示例会随列表变，用户想对照「改了参数会怎样」时就失去了参照）。

属性变量是**每个文件各不相同**的，所以这里要接一个决定：

> **采用「固定的假属性值」**，和「固定的假文件名【素材】」同一个思路：
> - 示例用的创建日期固定是 `2026-09-18`、修改日期固定是 `2026-09-02`；
> - 示例用的**大小固定是一个字节数（2 516 582 B）**，**按当前选中的单位实时渲染**。
>
> **好处**：改「大小单位」，示例立刻从 `2.4MB` 变成 `2516582B` → **单位是干嘛的，不用讲，看一眼就懂**（这正是 P3-1 用示例替代说明文字的同一个收益）。
>
> 示例行文案要跟着改成：**「示例（假的文件名 + 假的属性值，不是你列表里的文件）」** —— 必须把「假的属性值」也说出来，否则用户会以为那是自己文件的真实大小。

**明确不做**：不改 P3-1「不跟随列表真实文件」这个决定。

## 4. 算法与边界

| # | 边界 | 预期行为 |
| --- | --- | --- |
| 1 | 列表里**一个文件都没有** | 变量写在前缀里也照样渲染示例（示例用的是假值，不依赖列表） |
| 2 | 列表里**全是文件夹** | `{大小}` 全部展开成空串；`{创建}` / `{修改}` 照常有值 |
| 3 | 文件是 **0 字节** | `{大小}` = `0B`（**不是空串**，见 §1.4） |
| 4 | 文件在入列**之后**被外部改动 | 名字里仍是**入列时**的属性值（§1.3 的冻结语义）。**这是设计，不是 bug**，靠属性组的常显提示讲清 |
| 5 | 属性变量写在**原文件名**里 | **不生效**（`{n}` `{d}` 也一样）—— 变量只在前后缀里替换 |
| 6 | 属性变量写了但**打错字**（如把 `{大小}` 打成 `{大少}`） | 原样留在名字里（与 `{n}` `{d}` 的既有行为一致：不认识的占位符不特殊处理） |
| 7 | 选了 `GB` 但文件很小 | 得到 `0.0GB` —— 用户自己选的单位，照实渲染，不自动纠正 |
| 8 | 三个变量**同时**写进前缀 | 按出现顺序原样展开，互不干扰 |
| 9 | 10000 项 × 3 个新字段的内存 | 约几百 KB，可接受（`MAX_ITEMS_PER_BATCH` 已是 1 万） |
| 10 | 预览耗时 | 属性在入列时已读好，预览**不做任何 IO** → 与 P3-2 一样的目标：1000 项 < 300ms |

## 5. 我主动加的判断（都说明理由）

**① 不加「启用属性」开关。**
理由见 §1.2：属性没有「自动位置」，「开关」这个概念对它不成立。加一个勾会让用户以为「勾上就自动加进名字」。

**② 大小的小数位固定 1 位（B 档例外），不做第二个控件。**
`2.4MB` 够用；`2516582B` 必须整数（否则是假精度）。为了「1 位还是 2 位」再多一个下拉，是把一个几乎没人调的旋钮摆到主路径上。**真需要更细的精度，那是另一个需求，到时候再加。**

**③ 用「固定的假属性值」做示例，而不是改成读列表第一个文件。**
理由见 §3.5：改参数能立刻看到格式变化，才是示例的价值；而且这样**不改 P3-1 已经定过的决定**（只增不删）。

**④ 属性组的「属性」做成「展示 + 点一下插入」，不是输入框。**
用户在这里要的是「知道有这三个变量、并知道它们长什么样」，不是填值。点一下就追加到前缀末尾，比让用户手打 `{大小}` 少一次拼写错误。

**⑤ 把「今天」的本地日期算法下沉到 `shared/`，与属性日期共用一份。**
现在渲染层有一份 `todayString()`；本批要为「文件的属性日期」再算一次本地日期。**两份算法迟早会漂开**（一份用本地、一份不小心用了 UTC 就是差一天的 bug）。共用一份，并且**放 `shared/` 才跑得进单测**。

| **`DEC-07` 不持久化文件列表** | **不冲突**。属性随列表走，列表本来就不落盘；**零新增持久化字段** |

## 7. 改动面

### 7.1 类型与字段

```ts
// src/shared/types.ts

/** 一个文件在「加入列表那一刻」的属性快照 —— 之后不再刷新（§1.3） */
export interface ItemAttrs {
  /** 创建日期 YYYY-MM-DD（本地时区，来自 birthtime）。不可用时空串 */
  created: string
  /** 修改日期 YYYY-MM-DD（本地时区，来自 mtime）。不可用时空串 */
  modified: string
  /** 字节数。**文件夹为 null**（不可用），0 字节文件为 0（真的空）—— §1.4 */
  sizeBytes: number | null
}

/** 大小单位 */
export type SizeUnit = 'auto' | 'B' | 'KB' | 'MB' | 'GB'
```

`FileItem` **加一个字段**：

```ts
  /** P3-3：入列时的属性快照 */
  attrs: ItemAttrs
```

`RuleConfig.rule` **加一个字段**：

```ts
  sizeUnit: SizeUnit        // 默认 'auto'
```

> **`{创建}` / `{修改}` 的日期格式复用既有的 `rule.dateFormat`**（那 5 档）—— **不新增第二个日期格式控件**。属性组里用一句说明写清：「创建 / 修改日期用的是上面『日期格式』那一档」。这样用户改一次日期格式，`{d}` 和两个属性日期**一起变**，符合直觉、也少一个旋钮。

> **本批的静默形态比前两批更集中**：属性要在**四个形状**里传全。漏一个 → 属性在那个路径上**静默变成空串**，界面上一点异常都没有。

| # | 位置 | 不改会发生什么 |
| --- | --- | --- |
| 1 | **`PreviewItemInput`（`types.ts:532`）** | ★★ **本批最阴的一处。** 它的定义是 `Pick<FileItem, 'id' \| 'dirPath' \| 'stem' \| 'ext' \| 'isDir'>` —— 一份**显式字段白名单**。不把 `attrs` 加进 `Pick` 的联合，**Worker 就永远拿不到属性**：预览里 `{大小}` 展开成空串，而**界面完全正常**。注意 `Pick` 是**合法子集**，所以**类型检查不会报错** —— 这一处光靠编译器抓不到 |

## 15. 顺便记下的一个「想过但不做」

**不做「认不出的变量名给个提示」**（比如前缀里出现 `{大少}` 就提示「这个变量名不认识」）。

- **本来是个合理的保险**：现在有 5 个变量，打错字的概率确实上升了，而打错的变量名**不会报错、会被原样留在文件名里**。
- **但不做的理由更硬**：① 有了「点一下就插进前缀」，手打的概率已经很低；② 用户的前缀里**可能真的有** `{xxx}` 这种字面量（比如他就要这个名字），提示会变成误报；③ 既有 `{n}` `{d}` 也是这个行为，**本批不该顺手改既有行为的语义**。
- → 真要做，作为独立的一小批，和「变量高亮」一起做。

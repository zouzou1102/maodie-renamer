关于「90% 元素不一样」，我先说实话

六个分区里，D 和 E 是 6 个里换了 6 个（列表和状态栏在主界面直接没有了）；C 换了 5 个；A 和 B 各保留 2 个——就是「顶部标题栏」和「底部状态栏」。

保留这两个不是偷懒：标题栏是 Windows 的规矩（拖窗口、最小化在哪都是固定的），而且 「能看到原名和新名」这件事本身就是改名软件的本职，任何一种排版都躲不掉。所以我不给你编一个「89.3% 不一样」的数字——那没有意义。上面那张表就是全部事实，你扫一眼就知道哪几块还在。

如果你觉得 A、B 还是太规矩（它们确实更"像软件"），告诉我，我把它们也往 D、E 那个方向推。

PART 04刻意保持一致的六件事

有些东西不一致反而是错的。这六条五套都一样，是有意的。

画布 1440×900
五套都是这个尺寸，方便你并排比。窄到 900px 会整幅等比例缩小，不会出现横向滚动条。
同一只猫
五套用的是同一份内联 SVG（同一个 id="catfig"），连毛发毛边的滤镜参数都同一套。实测：五套里猫的像素完全一致——4776 个不透明像素、平均色 rgb(233,178,110)。
窗口外壳
拖拽区 + 最小化 / 最大化 / 关闭，五套一样。这是 Windows 规矩，不该各套一个样。
深浅两色都能切
右上角一点就切，不是只做了一套配色。我每套都拍了深浅两张图（共 10 张，在 shots/ 里）。
数字不跳
所有数字用等宽字形（tabular-nums），文件大小、序号、计数换行时宽度不会抖。
外部依赖 0
不联网、不引 CDN、不引字体文件、不引图标包。双击就能开，断网也一样。

PART 05老实话：没验到的和我确定做不到的

  1. 我看不了图片。这个会话的模型读不了图，所以「好不好看」我给不出判断——这是你的事，我确实看不到。前面每一句「没有溢出 / 没有截断 / 装得下」都是我用浏览器量出来的数字，不是我眼睛看到的。界面的美感请你亲自否定，我不会有情绪。
  2. Noto Sans SC 这台机器其实没装。我用宽度对比法测的（写成 Noto Sans SC 和写成一个根本不存在的字体名，量出来的宽度一模一样 = 走了回落）。所以上面五套的中文实际落在微软雅黑上。你原来的设计规范把 Noto Sans SC 列为主字体——要么把这台机器装上它，要么把字体栈里那一条删掉，不然换台电脑呈现会不一样。
  3. 只验了两个宽度：1440×900 和 900px。1024、1280、2K/4K 屏、以及 Windows 缩放 125% / 150% 的情况都没验。
  4. 数据是编的。五套里都是模拟的 6 个文件（IMG_2043.JPG 那一批），没接真实列表。真实场景里文件名会长得多，D 方案那种上下两行的排法遇到超长名会出现省略号——这是设计上接受的，但你要知道。
  5. 对比度：现在实测过了。这一条原来写的是「我用眼睛估的，不能算数」—— 现在不算数这句话要撤掉，因为我写了个自动审计：在浏览器里把 C 里每一个「有文字的元素」找出来，解析它实际压在什么底色上（含半透明层叠），按字号字重决定门槛（普通字 4.5:1、大字 3:1），再算真实的对比度。结果：深色 100 处、浅色 100 处，全部达标。过程中真抓到 3 类毛病并改掉了（见下一条）。仍然没验的是：朗读器读出来的顺序、键盘 Tab 键的走位、以及焦点环的可见性。
  6. 为了过对比度，C 的色板动了 6 个值（只有 C，另外四套没动）。这些不是我凭感觉调的，是「保持色相不变、只压明度」求出来的最小改动，改完再实测一遍：

    一句话：浅色的橘色比原来深了一档（从亮橘变成偏赭的深橘）。这是唯一一处你可能会一眼看出来的变化 —— 如果觉得太深，告诉我，我可以改成「换成中性灰底的高亮」这种别的解法，而不是把橘色压深。

  7. 这五套是原型，不是能直接塞进 Electron 的代码。它们现在是各自独立的 HTML 文件，验证排版和观感用的。你选定之后我再把它拆成 Vue 组件落进 maodie-renamer/，那时候要重跑 typecheck / lint / test:core / cli:verify / package:win 一整套，工作量不小。
  8. 猫的样子我没动。你说了「还是那只可爱橘猫」，所以五套里猫是同一只、同一个表情。如果哪一套你想让它的姿势或表情跟着变（比如 D 里当操作员戴顶帽子），说一声，这是单独的活。
  9. 只有 C 有动效，其余四套是静止的。这是你要求「面板太死板、要活跃一点」之后加的，不是四套漏了。动效我验到的是两件事：① 动画确实挂在元素上（读出来的名字是 panelIn / catbreathe / blink / ringDraw / breath，八块面板的入场延迟是 0.02→0.58s）；② 系统开了「减少动效」以后，这 5 项全部变成 none，界面静止。没验到的是：真机上的流畅度（每秒帧数）、放着不管半小时会不会累积跑偏、以及低配机器上会不会掉帧。这些得你在自己电脑上开着看一眼。
  10. C 在量尺寸时真抓到过一个毛病，已修。文件列表的第一行比其它五行矮 12px（46 / 58 / 58 / 58 / 58 / 58）。原因不是布局写错，是一个类名撞车：行的「选中」标记叫 sel，而下拉框的样式类也叫 sel，后者的 flex:1 把行的行高基准覆盖掉了。改名成 is-sel 之后六行实测都是 56px。这类毛病肉眼看只是「第一行好像有点扁」，不量尺寸根本说不清 —— 所以我是量出来的，不是看出来的。
